# 📚 Kira Wiki · 知识晶格

> 让 AI 帮你把零碎素材编译成一本会自己长出来的知识库

**Kira Wiki**（插件 ID `KiraAI_kira_wiki_plugin`）是 [KiraAI](https://github.com/xxynet/KiraAI) 框架的插件，灵感来自 Karpathy 的 [LLM Wiki 思路](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f)：**LLM 就是编译器，Obsidian 就是 IDE**。

你只管把素材（文章、笔记、聊天记录、随手抄的东西）丢进去，AI 会自动帮你整理成结构化的 wiki 页面，还带互相引用的双链，用 Obsidian 打开就是一张知识图谱。

---

## 兼容性

支持 KiraAI 2.33.1+ 与 3.0 全系列（含 v3.0.0-rc.1 / rc.2；特征识别，不绑版本号）。
两代都做过**真框架端到端冒烟**：`python tools/panel_smoke.py --framework <KiraAI 源码根>`（61 项断言，全绿）。
**v1.1.1 起 `model` 是下拉选择**（`model_select`，走框架的模型配置）：在插件设置里直接选，不用手抄任何 ID。
历史配置里手填的「服务商:模型名」仍然可用 —— 插件启动时会自动解析并**迁移成下拉值**（迁移结果回写配置文件，
下拉框立即正确回显）；解析不出来时告警并回退默认 LLM，不会静默失效。

历史写法（仍兼容）：**v1.0.1** 补上了「可读模型名 → 内部稳定 ID」的解析（rc.1 框架只认内部 ID/迁移旧名）；
**v1.0.2** 补上了「服务商显示名（如 `Agnes（CN）`）→ 实例 ID」那一半。解析不到时**告警 + 回退默认 LLM**
（此前会静默返回空串，表现为「wiki 生成没反应」）。

| 写法 | 2.x | 3.0 rc.1+ |
| --- | --- | --- |
| **下拉选择**（v1.1.1+ 推荐） | ✓ | ✓ |
| `提供商显示名:可读模型名` | ✓ | ✓（v1.0.2+） |
| `实例ID:可读模型名` | ✓ | ✓（v1.0.1+） |
| `实例ID:内部ID` | ✓ | ✓ |
| 留空 | 用框架默认 LLM | 同左 |

**v1.1.0**
- 工具精简 **5 → 4**（`wiki_list` + `wiki_lint` 合并为 `wiki_status`，`check=true` 出完整体检）；
  工具 schema 每轮请求都会注入，少一个工具就是少一份常驻 token。
- 全部磁盘操作移出事件循环（`asyncio.to_thread`，共 37 处）：大库扫描不再阻塞聊天。
- 检索改为**关键词排序 + 字符预算**（默认 8 页 / 14k 字符），不再把整库塞进 prompt。
- 新增**侧边栏面板**（见下）。
- 本插件**不注入任何系统提示词**（无 `on.llm_request` 钩子），因此不会破坏 prompt 前缀缓存。

## 🖥️ 侧边栏面板（v1.1.0）

在 KiraAI 主 WebUI 的侧边栏点「知识库」进入。设计语言：墨/纸双主题、Lucide 图标（内联 sprite，
无 CDN、无 emoji）、力导向晶格画布。

| 区域 | 能做什么 |
| --- | --- |
| 自举引导 | 没有知识库时不再是一句报错：给出一键「创建 / 接管这个目录」，也能把已有 Obsidian 库指过来 |
| 库切换 | 顶栏下拉在多个知识库之间切换（选择记在本地） |
| 知识晶格 | 全库 wikilink 图：拖拽节点、滚轮缩放、双击聚焦、悬停点亮邻域；左栏分区可过滤；**外部笔记**单独一色 |
| 阅读抽屉 | 点节点打开页面：frontmatter 单独成块，`[[wikilink]]` 可点击跳转（断链为虚线下划线） |
| 热编辑 | 抽屉右上「铅笔」进入编辑（或按 `E`），`⌘/Ctrl+S` 保存，未保存有状态提示；保存即写回 `wiki/*.md` |
| 搜索 | 顶栏搜索框（或按 `/`）：关键词排序命中，命中页自动高亮 |
| 问答 | 右上「sparkle」（或按 `A`）：走与工具同一条检索链，回答标注参考页面，可点来源跳转 |
| 体检 | 右上「pulse」（或按 `L`）：空页 / 断链 / 孤立页清单 + 分区统计 |
| 索引 | 右上「refresh」（或按 `G`）：按实际页面重建 `index.md` |
| 新建 | 右上「plus」（或按 `N`）：在指定分区建页并立即打开编辑（**页内表单**，不依赖浏览器弹窗） |

**两条硬边界**（前后端一致）：

1. **只读操作绝不落盘** —— 浏览、体检、搜索、看图都不会在你的目录里创建任何东西；
   建目录只发生在显式的「创建 / 接管」、收录、写页、重建索引。
2. 所有读写都经 `resolve_rel()` / `resolve_target()` 校验，只允许**知识库根之内**的相对路径 `.md`；
   `../`、绝对路径、盘符一律 400 拒绝；原点为「笔记区」时禁止落到 `wiki/`、`raw/` 与隐藏目录里。

> ⚠️ 面板**不使用原生 `prompt/confirm`**：KiraAI 插件页 iframe 的 sandbox 没有 `allow-modals`，
> 浏览器会静默吞掉模态框（表现为「按钮点了没反应」）。所有输入与确认一律走页内自绘 modal。

## ✨ 它能干什么

AI 通过 **4 个工具**操作知识库。**其中 2 个完全不调用模型**——bot 自己就能建库、写页、改页、删页：

| 工具 | 调模型？ | 作用 |
| --- | --- | --- |
| `wiki_write` | **否** | `mode=replace` 整页写入 / `append` 追加 / `delete` 删页 / `init` 建库或接管目录（`path` 可省略）。生成区与**你自己的笔记区都能写**；核心页 `index/overview/log/conventions` 受保护 |
| `wiki_read` | **否** | 给 `ref` 读该页完整正文；不给 `ref` 列出全部分区与统计，`check=true` 顺带体检（空页 / 断链 / 孤立页）。改页前先读原文 |
| `wiki_ingest` | 是 | 收录素材进 `raw/`，并让生成模型编译摘要/实体/概念/分析页；**模型不可用时只存 raw 并明确提示改用 `wiki_write`** |
| `wiki_query` | 可选 | **检索**知识库。`ask=true`（默认）让生成模型写成带出处的答案；`ask=false` **零模型调用**，只返回按相关度排序的命中列表（rel / 标题 / 分区 / score / 片段），要全文再用 `wiki_read` 钻取；模型不可用时自动退化成后者 |

## 🗂️ 目录结构

一个知识库（Obsidian vault）长这样：

```
data/kw/                  # 默认知识库（可在配置里改路径）
├── raw/                  # 素材区（你丢东西进来，LLM 只读）
│   └── assets/
├── 我的笔记.md           # ← 你自己的笔记（知识库根 + 任意子目录），可读可写
└── wiki/                 # AI 生成区（LLM 自动维护）
    ├── index.md          # 自动重建的索引
    ├── overview.md       # 总览
    ├── log.md            # 操作日志
    ├── conventions.md    # 使用约定
    ├── sources/          # 每篇素材的摘要页
    ├── entities/         # 实体页（人物/组织/工具）
    ├── concepts/         # 概念页（理论/方法/模式）
    └── analyses/         # 分析页（综合论述）
```

## 🚀 快速开始

1. 把插件目录放进 KiraAI 的 `data/plugins/` 下，重启或热重载
2. **零配置即可用**：侧边栏点「知识库」→ 面板给出默认目录（`data/kw`）→ 点一次
   **「创建 / 接管这个目录」** 就建好了。**也可以直接把它指向你已有的 Obsidian 库**：
   里面的笔记会被一并载入晶格与检索，可读可写，插件不会擅自改动它们。
3. 对 bot 说：**「建个知识库」**（`wiki_write mode=init`，`path` 可留空，用默认路径）
4. 让 bot 自己写：**「把这个记进知识库：……」**——bot 会直接用 `wiki_write` 落笔，
   **不调用任何额外模型**；想要自动编译成摘要/实体/概念页时再用 `wiki_ingest`
5. 用 Obsidian 打开知识库目录，看图谱、看双链，完事；面板里也能读、能改、能问答

> 没装 Obsidian？纯文本编辑器也能看，只是没有图谱和双链跳转；面板里也能读能改。

## ⚙️ 配置

`schema.json` 里两个配置段（WebUI 设置页直接渲染）：

- **常规**
  - `enabled`：开关，默认开
  - `default_kw_path`：默认知识库目录，默认 `data/kw`（相对 KiraAI 根目录），不填的话每次要指定知识库名
- **模型**
  - `model`：**下拉选择**用于生成 wiki 页面的模型（`model_select` / `model_type: llm`），留空用 KiraAI 默认 LLM
  - `max_pages_per_ingest`：单次收录最多生成的页面数，默认 15

> 面板顶部会显示当前生效的生成模型（与配置同源）；若配置的模型解析不到，会以警示色提示并回退默认 LLM。

## 🧠 工作原理（一句话版）

你丢素材 → 存进 `raw/` → LLM 读素材，输出 JSON（摘要/实体/概念/分析）→ 插件把 JSON 写成带 `[[wikilink]]` 的 md 页面 → 更新索引和总览 → 完事

LLM 生成失败也不慌，素材已经躺在 `raw/` 里了，不会丢。

## 🛠️ 开发

模块划分：

| 文件 | 职责 |
| --- | --- |
| `main.py` | 插件入口：4 个工具 + 11 个面板 API + 页面注册 |
| `wiki_core.py` | 服务层：路径安全、索引、图、检索排序、体检（纯标准库、可单测） |
| `web/` | 面板前端：`index.html` / `style.css` / `app.js` / `graph.js`（零依赖、Lucide sprite 内联） |
| `assets/menu.svg` | 侧边栏菜单图标（Lucide 风格） |

- 工具走 KiraAI 的 `@register.tool`；面板接口走 `@register.api`（全部 `auth=True`）；页面走 `@register.page`
- 磁盘操作一律 `asyncio.to_thread`，不在事件循环里做同步 I/O
- 模型解析：`_canonical_model_ref()` —— 先直传 `ctx.get_llm_client()`，失败再走 `provider_mgr` 显示名反查；
  解析结果用于「迁移配置」与「面板芯片」，一处逻辑两处复用（2.x / 3.0 双世代）
- 无第三方依赖（`wiki_core.py` 纯标准库）

### v1.4.0 —— `wiki_query` 可以当纯检索用
- 🔍 新增 `ask` 参数（默认 `true`，与旧行为一致）。`ask=false` 时**完全不调用生成模型**，
  返回紧凑命中列表：`rel · 标题 · [score]` + 200 字片段，最多 12 条，

- 💡 为什么默认值保持 `true`：`ask=true` 的合成发生在**另一个调用**里，主对话只多约 200 字答案；

- 🖥 面板 `POST /query` 同步支持 `ask: false`（返回 `hits` 数组）；面板搜索框本来就是纯检索。
- 未命中时不再只说「没有页面」：会说明库里有多少可检索页面，并提示换个词或列目录。
- 🪶 顺手把四个工具的描述又压了一轮（语义不变，动作列表只保留一处）：
  工具 schema 总量 1585 → **1566 字符**；骨架（JSON 语法）646 + 语义 673，
